# Workflows

Task SOPs. **Distinct from `docs/MISSIONS.md`**, which defines *who* runs (team composition). These define *how a specific task is done* (procedure).

| | `docs/MISSIONS.md` | `workflows/` |
|---|---|---|
| Answers | Which agents to spawn | How to perform a task |
| Scope | A whole mission | One repeatable procedure |
| Changes | Rarely | Every time you learn something |

## Writing one

Copy `_TEMPLATE.md`. **Write it after you've done the task twice**, not before — a workflow written from imagination is a guess, and guesses are what SOPs are supposed to eliminate.

## The rule agents follow

They read the workflow, identify the tools, run them in sequence, handle failures, and append to "Learned constraints." They do **not** create or overwrite a workflow without asking.
