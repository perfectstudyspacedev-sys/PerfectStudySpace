# Git Rules

- Keep commits focused and understandable.
- Do not rewrite shared history without explicit approval.
- Do not commit secrets, build artifacts, generated credentials, or local machine state.
- Inspect the diff before committing.
- Do not mix unrelated refactors with feature work.
- Use isolated branches/worktrees for parallel implementation when practical.
- Make commit/PR messages describe the user-visible or engineering outcome.
